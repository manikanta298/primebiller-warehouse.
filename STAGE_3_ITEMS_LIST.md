# Stage 3 — Items List review checkpoint

**Route:** `/items` (signed in as Owner, Manager, Storekeeper, Sales, or Accountant). **Scope:** Items *list* only, not the item detail/edit tabs or item creation form, which remain for separately approved stages.

## What is implemented

- **Layout preserved:** the source application's Masters / Items header, four KPI strips, the search input and the seven columns (Item / HSN / GST / On hand / Held / Free / Sale price). Item names continue to open the original `/items/:id` detail route. Table scrolls horizontally on small devices.
- **Org isolation:** React Query's cache key includes the signed-in organisation; the real API already filters `GET /api/v1/items` by the JWT's `X-Org-Id`, and the demo mode now tracks item ownership explicitly, including items imported with no stock yet. Switching organisations resets the search/filters/page. Mock item read/update also reject another organisation's items.
- **Godown-aware metrics:** summary cards and stock columns recalculate for the godown selected in the app shell. “Stock value” means **on-hand × item cost**, and only active items count toward all four KPIs. Held reservations affect free stock; stock alerts are distinct from stock quantity. Search/filters affect the list, **not** the organisation/godown-wide KPI cards.
- **Working controls:** tokenised case-insensitive search against name, SKU, HSN, brand and category; category, stock and active-state filters; six sort choices; 25-row pages with Previous/Next and match counts; Clear filters; contextual no-data and failed-request states.
- **Actions:** Item link opens existing detail page; **Import items** opens existing bulk import screen only for Owner/Manager, as dictated by shared permissions; **Export CSV** downloads all currently filtered and sorted results (not just one page), scoped to the selected godown. Text fields are CSV-quoted and spreadsheet formulas are neutralised before export.
- **Shared rules:** `src/lib/item-list-rules.ts` contains stock status, KPI, filter/sort, pagination, and CSV rules. The standalone backend ships the generated copy `backend/src/shared/item-list-rules.ts`, regenerated by `node scripts/sync-shared.mjs`. No new API endpoint, MySQL migration, or Docker change was needed; the original complete schema and runtime are still included.

## How to review

1. Copy `.env.example` to `.env`, fill in secrets, and run `docker compose up -d --build`. On a fresh database, create your first Owner using the instructions in `CONVERSION_STATUS.md`; preserve `mysql_data` when upgrading from Stage 2.
2. Sign in and open `http://localhost:8080/items`. If using a clean live database, import or create items before checking non-empty screens; the real database is deliberately unseeded. In local demo mode without `VITE_API_URL`, the supplied sample items are available.
3. Change the godown in the app shell. Verify the four KPIs, on-hand/held/free columns and stock condition filter change together; verify the other godown or organisation does not leak records.
4. Exercise name/SKU/HSN/brand searches, combined filters, sorting, empty/no-match states, disabled import action for non-editor roles, item detail navigation, exported CSV and pagination with more than 25 items.
5. Check the layout at desktop and mobile widths against your original Items screen. The existing code/layout has been retained, but an exact pixel comparison requires screenshots/running browsers.

## Automated checks

`npm run test:items` runs six native Node.js tests: godown and held stock calculations, active-only KPI totals, multi-token search and combined filtering, six sorting modes with deterministic tie-breaking, pagination bounds, and CSV escape/formula prevention. `npm run test:conversion` also runs all five Stage 2 dashboard tests. Modified TS/TSX files received an additional TypeScript syntax/transpilation check.

## Verification limitations

No Docker engine or installed frontend/backend `node_modules` were available in the packaging environment. A full React TypeScript typecheck, live authenticated MySQL API integration test, Docker container boot, SMTP integration, and screenshot/pixel-perfect visual comparison **have not been run** here. Production-sized catalogues will benefit from server-side pagination; this stage intentionally loads the authorised organisation's item catalogue once to keep the four KPIs independent of search filters.
